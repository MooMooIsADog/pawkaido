# 东海岸案例：哪些做法值得复用

这是已发生的设计迭代，不是所有新地图必须照抄的规定。历史证据在仓库 `artifacts/east-coast-maps-v1/`、`artifacts/east-coast-maps-v2/`；对应的提示词、检查图、中心线和旧包配置都在那里。优先用当前代码核验，不运行历史脚本改变新包。

| 观察到的问题 | 原因 | 有效处理 |
|---|---|---|
| 画风接近写实插画，地标虽然清楚但不像卡通 | “复古旅行海报”不能充分限定渲染方式 | 明确墨线、简化色块、卡通树冠和去掉写实叶片；保留建筑轮廓后再用于跨章风格参考 |
| 大宅/桥等地标容易变成泛用建筑 | 名称不足以约束形状 | 写出屋顶、柱廊、桥塔、配重等识别特征；参考照片逐项验收 |
| 肖像或雕像太小，彩蛋看不出来 | 只描述存在，没有说明正常游戏缩放下要可辨认 | 给相对画面尺寸和识别特征；脸也必须匹配卡通画风，不粘贴照片 |
| 原路有小波浪但站点依旧拥挤，左上大片陆地闲置 | 整条路仍是右上到左下的短斜线 | 重排构图、删除旧路、做横穿内陆的两个大弯，腾出景观与文字带 |
| 通过隐藏地点名暂时减轻拥挤 | 把布局问题转成了交互负担 | 先拉长路径，再恢复常驻名称，检查多尺寸下的碰撞 |
| 图路和动画不贴合 | 采用估计坐标或对子路线重新拟合 | 对最终图片描路面；绘图、按钮、进度和行走共用完整点集的曲线 |
| 沿路均匀，但回头弯两侧仍可能互相挤 | 只检查相邻序号，没有检查任意两站的屏幕距离 | 同时看弧长与所有站点对的直线距离，再做 DOM/视觉检查 |
| 左下终点标签压住路线说明；小屏标题压住路标 | 背景留白没有计算覆盖 UI | 将说明挪到闲置海面，小屏缩短标题，不移动规则站点或隐藏名称 |
| 新地区配置看似完整仍不能直接交付 | 包总数测试、CSS ID、ZIP 白名单、平台导出是固定逻辑 | 接入前显式检查这些文件，按本次新增包小范围适配 |
| 原图要求永久保留，但运行资产还需压缩修订 | 把原图和运行文件当成同一份资产 | 原图按版本只读归档和哈希锁定，派生 WebP 另存，旧副本保留回退但不混进新 ZIP |
| 系统 AAC 构建在沙箱里报编码器错误 | 案例中是沙箱无法访问系统编码服务，不是音乐需要重做 | 本地授权构建重试后成功；遇到类似错误先定位原因，不硬编码某台机器的解决方式 |

东海岸 v2 的四条路在 1536×1024 原图上约为 3679/3386/3410/3588 px，距离扩大后平均每站沿路约 244–276 px。这些是案例数值，不是新地区的目标阈值。路径更长仍不能替代截图检查。

旧 v1 检查记录保留了自由女神岛与岸线、倒影池与河流的艺术化问题；旧原图已由用户指定保留，不能为了统一版本“顺手修掉”。新地区应主动在生成/修图阶段检查这些地理关系。

本 skill 不要求重新创造狗狗、动画、玩法或音乐。反复验证的目标是新增内容能融入现有游戏，而不是扩展任务范围。
