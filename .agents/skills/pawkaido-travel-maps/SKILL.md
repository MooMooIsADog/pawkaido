# Pawkaido 旅行地图内容包

把一个旅行地区做成可玩的四章地图，而不是只交付四张背景图。默认沿用项目中的四只狗、标准版地点和可选心愿规则；按用户要求决定交付美术预览、修图还是完整接入。

本 skill 随仓库保存在 `.agents/skills/pawkaido-travel-maps/`，命令从 Pawkaido 仓库根目录运行。`$SKILL_DIR` 在示例中表示这个相对路径。换 checkout 时重新定位根目录，不使用作者电脑的绝对路径。

## 先确认当前边界

- 读取适用的 `AGENTS.md`、`git status --short`、`package.json`、`dist/map-content.js`、`dist/map.js`、目标地图包；保留已有未提交修改。
- 这是**地图内容包**，不是 `dist/extensions/` 里的玩法扩展。不要为了换路线改 `engine.js`、`data.js`、`scores.js`、心愿条件或 AI。
- 新地区用新包 ID；同一地区修图保留 ID、递增版本。原始素材独立归档，运行素材用派生副本。已要求保留的原图不得覆盖，也不得更新旧哈希来掩盖变化。
- 用户已经确定的路线、画风、地标和彩蛋优先；缺少非关键细节可以做出合理选择。只在缺少会实质改变路线的信息时提问，已有授权无需再次征求批准。
- 现有地图接口有固定假设，不能承诺“丢四张图进去就完全自动”。接入前阅读 [接口与兼容边界](references/integration.md)。

## 工作流程

### 1. 先把旅行做成棋盘布局

按实际路线分成四段，建立包含五个驿站端点、每章代表地标、风景/农庄/小铺等主题映射的简短表格。地点类型和数量来自当前 `BOARD/INNS`，不按现实景点数量改变规则。标准四人版目前是 55 个位置、五个驿站；各章显示 15/14/15/14 个站点（相邻章节共用驿站）。

真实地标需识别性依据，先查可靠图文参考；记录链接和需要保留的轮廓。虚构纪念小景明确说明，不把它描述成现实存在。朝向随地区和用户要求确定，不把美国版的右上→左下强加给所有地区。

**先留道路和文字的空间，再安排景观。** 对密集斜线路线，扩大内陆绕行和弯道覆盖范围；不要靠增加微小波浪、缩小节点或隐藏名称解决拥挤。详见 [绘图与修图](references/art-workflow.md)。

### 2. 绘图、检查、按问题修图

有绘图工具时使用它生成/编辑实际位图；可用的 imagegen skill 负责该环境的工具调用细节。没有绘图工具时，可以先完成路线设计、提示词和接入准备，明确缺失资产；不擅自切换收费 API 或索要密钥。

每张单独生成，参考图注明角色（风格参考、编辑目标或地标参考）。局部错误做局部修订；路线拓扑错误则重排构图。每轮保留文件、提示词、检查结论。接受用户“先画一张看看”的阶段边界，不提前生成或接入余下内容。

### 3. 保护原图并生成游戏副本

建议目录：`artifacts/<pack-id>-maps-vN/` 保存 PNG、提示词、来源和检查结果；`dist/map-packs/<pack-id>/assets/vN/` 保存运行 WebP。已有文件另建版本，避免覆盖。

新归档可以用本 skill 的 [原图清单脚本](scripts/artwork-manifest.py) 创建 SHA-256 清单并设只读；旧归档只能校验，不重新盖章。只读权限能被文件所有者解除，必须同时保留哈希和目录保护说明，不能把它宣传成不可更改的备份。

### 4. 贴合路面标定，再接入包

在最终位图上人工描出连续路面中心线，记录图像尺寸和像素坐标。用 [路线编译脚本](scripts/compile-routes.mjs) 生成百分比坐标、按弧长分布的站点索引和间距指标；它只写新输出文件，不改生产代码。不要直接运行历史 `build-routes.mjs` 为新地区编译，它固定了东海岸包路径。

绘制道路、站点定位、进度线、狗狗动画必须使用同一条 `roadPath`。逐段曲线控制点必须与完整路线一致；不能把子路线控制点重新拟合。操作方法和检查见 [路线与验证](references/geometry-qa.md)。

按 [接口文档](references/integration.md) 添加配置和 catalog，适配主题名称、MooMoo 第一人称风景介绍、路书和结算。地图选择与经典/心愿玩法选择分离。不以全局替换 HTML 或改卡牌数据实现换皮。

### 5. 以实际游戏验收

运行相关测试、原图校验、打包检查；用隔离端口/来源验证，避免替换用户正在玩的存档。浏览器确认四章、地点文字、放大/列表视图、沿路动画、读档与取消新旅行，以及主题文案。需要时再运行同种子规则对照，不能用“文件没改”代替行为证据。

默认不隐藏地点名称来通过检查。检查名称之间、名称与别的按钮、标题与按钮、狗狗精灵与边缘的遮挡；真实截图与 DOM 尺寸互相补充。既看普通窗口，也看窄窗口。保存可复核截图，恢复临时视口设置并关闭临时服务。

## 交付

说明可玩的本地入口、当前选择方式、原图/新版素材/地图包位置、绘图工具与提示词、验证结果和剩余限制；展示实际接入后的截图。区分“生成了”“接入了”“浏览器验证了”。本任务不自动授权 commit、push 或发布。音乐没有改时如实说明。

需要排查时阅读 [东海岸案例与常见误区](references/lessons.md)，不要把该案例的像素坐标、角色彩蛋、固定端口或平台体积限制当成所有地图的要求。
