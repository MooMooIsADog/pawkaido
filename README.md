# 汪汪东海道 · Pawkaido

MooMoo、Yuki（哈士奇）、Biscuit（柯基）和 Rex（德牧）的本地浏览器旅行桌游。以《东海道》标准版四人规则为基础，角色、餐食、收藏与场景改成狗狗主题。支持可选的狗狗喜好扩展；没有账号、在线服务、外部字体或远程 AI。

## 开始

```sh
cd pawkaido
npm start
```

打开 http://127.0.0.1:4175/ 。只依赖 Node.js，无需 npm install。端口可用 `PORT=4177 npm start` 修改。`package.json` 的 `private` 只防止误发布 npm 包，不是登录或访问限制。服务只监听本机。

- 默认：MooMoo 由玩家控制，其余三只为本地 AI。
- 四人同屏：四只狗狗全部由玩家轮流操作。
- 开局随机分配两种旅人能力，选择一种；十种标准版能力完整保留。
- 点击地点查看规则与不可前往的原因，再点“带我去这里”。
- 选择和事件都在棋盘中央弹窗中完成。“全程路书”可以查看后续三段路线。
- 本地自动存档包含当前事件与牌堆，刷新不会重新抽牌。音乐音量单独保存。
- 音乐默认关闭，点击“播放音乐”开始。使用浏览器原生音频循环，不需要外部音频服务。

## 实现范围

标准版地点顺序：55 个位置，含京都起点和 14 / 27 / 41 / 54 号必停驿站。保留四人版双人空间、最靠后行动、外侧先行、四阶段共享菜单、不可重复用餐、24 件四类伴手礼、25 张鲜食卡、12 张泡汤卡、14 张相遇卡、三幅 3/4/5 片画卷、7 种成就与神社终局排名。

十种能力在 `dist/data.js` 保留原旅人名称作为规则映射，显示名称为原创狗狗版本。各狗都可以抽到任意能力。三位 AI 使用同一规则引擎，按公开信息估算收益与前进距离、预留饭钱；只处理已经翻给自己的牌，不读牌堆，没有额外资源。

采用标准版四人对局 + 三个电脑玩家，不采用新版实体单人规则。画面以当前路段为主；全程路线可随时查看。餐食、物品、驿站的狗狗名称与插画是主题改编，驿站名称不是历史地理考证。

## 音乐与美术

《樱风里的小爪印》为本项目原创合成小曲：D 调 yo 五声音阶（D/E/G/A/B），4/4 拍，64 BPM，60 秒循环。筝风格拨弦、呼吸感笛声和轻木敲音，均为本地数学合成，不使用采样录音。脚本 `scripts/compose-music.py` 用 Python 标准库生成 stereo 32 kHz WAV。环形混响和尾音跨接保证循环连贯。

四只狗狗复用现有 Moonopoly 精灵图和帧表；没有改动旧游戏。`dist/assets/landscape.svg` 为本项目原创场景。未使用原桌游图像或抄录规则书文案。

## 浮世绘地图（2026-10-25）

主棋盘已改为四幅浮世绘区域地图，随旅程切换：京都近江、伊势三河、骏河富士、箱根江户。游戏地点以可点击的圆形路标叠加在蜿蜒道路上，狗狗精灵位于实际停靠点；绿色虚线圈表示可前往。默认按窗口完整缩放；“放大地图”查看细节，“定位狗狗”定位当前行动角色，“地点列表”切回清楚的地点卡片。窄屏缩览会省略地点名称，点击路标可查看完整详情，放大后也会恢复名称。

地图为艺术化区域绘卷，地形和地点间距按桌游布局处理，不作为现实导航或历史驿站位置图。区域地景参考日本国土交通省对旧东海道沿线、箱根与芦之湖的介绍：
- https://www.ktr.mlit.go.jp/yokohama/tokaido/02_tokaido/04_qa/index1/a0104.htm
- https://www.ktr.mlit.go.jp/yokohama/tokaido/02_tokaido/01_aruku/1100.htm

背景由内置 imagegen 生成，保存为 `dist/assets/ukiyo-map-atlas.png`。四个区域使用同一张 2 × 2 图集，通过 CSS 裁切展示，不依赖在线图片服务。最终完整提示词见 `artifacts/ukiyo-map-prompt.txt`。路线与交互坐标在 `dist/map.js`，显示样式在 `dist/map.css`；玩法引擎和旧存档格式未变。

## 道路行走与终局账单（2026-10-25）

四只狗狗移动时沿地图上同一条 SVG 曲线前进，按行进方向切换左右奔跑动作，到站后才出现事件。跨过的地点不会触发额外收益。普通速度约 1–4.6 秒，AI 快速模式同步缩短动画；系统开启减少动态效果时直接显示到站事件。放大地图会跟随狗狗横向移动，列表视图下前进会临时展示地图。行走期间暂停其他游戏操作和 AI 调度，音乐控制仍可使用。

合法行动在动画前只提交、存档一次；刷新途中会恢复到已确定的到站事件，不重复抽牌或加分。`dist/walk.js` 负责视觉移动，`map.js` 的子路线保留完整道路的控制点。

终局有四只狗狗各自的第一人称账单，可以点击排行榜的“分解”跳转。九类分数逐项列出：画卷、伴手礼、鲜食、泡汤、旅途捐赠、相遇直接得分、能力直接得分、成就、捐赠排名。说明区分已计入泡汤/成就等项目的能力奖励，不重复累加；金币余额不换分。`dist/scores.js` 读取实际 ledger 并生成说明。

新增两项表现层测试，总计 25 个测试：所有可用道路子段与完整曲线逐段一致；另跑 40 局完整模拟，覆盖十种能力，核对所有玩家分项和总分一致。

## 狗狗能力扩展版

新旅行可以选择经典版或狗狗能力扩展版。扩展版保留原有十种旅行能力，额外增加固定喜好：MooMoo「大馋丫头」在三个中途驿站各吃饭一次 +6；Yuki 完整收集稻田 3 片、山景 4 片、海景 5 片（停靠、相遇赠送、旅行能力均计入），全部完成 +6；Biscuit 在三个不同汤屋成功泡汤 +6；Rex 帮忙两个不同农庄 +4。

心愿完成时立即加分，仅奖励一次，独立记入账本，不增加成就卡数或触发老行家成就加分。免费餐计入 MooMoo 进度，江户用餐不补中途缺餐，新开局赠送画卷计入 Yuki 收集进度。没有版本标记的早期存档按经典版读取；已有心愿存档保留当局条件与奖励。

运行 `npm test` 验证规则；`npm run balance -- 1000` 跑两种选能力策略各 1,000 对经典/扩展对照；`npm run balance -- 1000 unaware` 跑不追求喜好的 AI 对照。结果在 `artifacts/wishes-balance*.json`，方法和结论见 QA.md。

2026-10-26 调整：新开局 Yuki 改为三幅风景全部集齐（3/4/5 片）、赠送也计入、完成后 +6 分。条件和奖励随本局存档保存，之前的扩展局仍按原有条件（各一次、各停靠两次、各收集两片或三幅全齐）与当局的 2、3 或 4 分继续，避免读档丢失或重复修改已有分数。

## MooMoo 讲风景

地图工具栏的「MooMoo 讲风景」会介绍当前卷的插画、代表景物与旅程含义，使用 MooMoo 形象和第一人称口吻。全程路书的四幅缩略图也各有介绍入口。阅读时暂停 AI 调度，关闭后返回原界面；不推进回合或更改存档。说明随地图卷切换，适配窄屏。

## 本地扩展结构（2026-11-01）

在 `v1.0.0` 上重组已有心愿功能，玩法与分值不变。心愿规则、AI 偏好、存档校验和专属展示集中在 `dist/extensions/dog-wishes/`；本体通过事件、计分效果和展示接口调用它。扩展仍随游戏附带，开局照常选择经典版或狗狗能力扩展版。

已安装包在 `dist/extensions/catalog.js` 注册；新存档记录扩展编号和版本，旧存档保留原有条件。缺少包或版本不兼容时会提示恢复对应扩展，不会自动把该局当成经典版。

`npm test` 包含原有玩法测试及扩展安装、移除和兼容检查。`npm run compare:refactor -- 1000 v1.0.0` 与旧版本逐步比较两种 AI、两种游戏模式共 4,000 组同种子对局，并输出 `artifacts/dlc-refactor-comparison.json`。

安装、独立 ZIP 打包、接口和当前支持范围见 [扩展开发说明](docs/extensions.md)。当前是本地模块与内容包机制；没有自动下载、在线发布或多扩展组合功能。
